# PLAN.md — Universal File Converter (Python + CustomTkinter)

## 1. Твоя роль и главная задача

Ты работаешь как Senior Python Developer и должен реализовать полноценное desktop-приложение **Universal File Converter** согласно требованиям из документа `projekt-1-konwerter.pdf`.

**Главная цель:** создать готовый, запускаемый и протестированный проект, в котором все заявленные функции действительно работают. Это не прототип, не демонстрационный макет и не набор заглушек.

Перед началом разработки внимательно изучи `projekt-1-konwerter.pdf` целиком, включая таблицы, критерии оценки, минимальную матрицу тестов, пример архитектуры и требования к сдаче. Используй документ как основной источник требований.

### Обязательные технологические решения

- Python 3.11+.
- **CustomTkinter** — единственная основа графического интерфейса. Не используй стандартные Tkinter/ttk-виджеты для построения интерфейса.
- `pathlib` для работы с файловыми путями.
- `csv`, `json` для структурированных данных.
- `python-docx` для DOCX.
- `odfpy` для работы с ODT, если соответствующие операции не делегируются LibreOffice.
- `reportlab` для генерации PDF из TXT.
- LibreOffice в headless-режиме для конвертации офисных форматов, где это необходимо.
- `subprocess.run()` для запуска внешних процессов без `shell=True`.
- `pytest` для автоматических тестов.
- `logging` для записи ошибок и результатов операций.

Можно использовать дополнительные библиотеки, если они действительно необходимы. Все зависимости должны быть обоснованы и задокументированы.

Не заменяй CustomTkinter на PyQt, PySide, Kivy, веб-интерфейс или другую GUI-технологию.

## 2. Обязательные требования задания

Реализуй все следующие пункты.

### 2.1. Конвертация файлов

Приложение должно поддерживать не менее шести работающих направлений конвертации, охватывающих три группы:

1. Структурированные данные: CSV и JSON.
2. Текстовые файлы и документы: TXT, DOCX, ODT, PDF.
3. Офисные форматы: DOCX, ODT, PDF.

Недостаточно просто показывать форматы в интерфейсе. Каждый заявленный конвертер должен реально создавать корректный файл.

### 2.2. Графический интерфейс

Пользователь должен иметь возможность выполнить полный цикл работы без терминала:

1. Выбрать исходный файл.
2. Увидеть его имя, путь, расширение и размер.
3. Выбрать каталог назначения.
4. Увидеть только поддерживаемые форматы для данного исходного файла.
5. Выбрать целевой формат.
6. Запустить конвертацию.
7. Видеть текущий статус и ход выполнения, где возможно.
8. Получить сообщение об успехе с путём к результату.
9. Открыть каталог с результатом.
10. Получить понятное сообщение при любой ожидаемой ошибке.

### 2.3. Безопасность и корректность

- Проверять существование исходного файла и то, что это обычный файл.
- Проверять корректность расширения и поддерживаемость пары форматов.
- Проверять наличие необходимых библиотек и внешних программ.
- Проверять возможность записи в каталог назначения.
- Не перезаписывать существующий файл без подтверждения пользователя.
- Не запускать конвертацию при незаполненных или некорректных параметрах.
- Не допускать зависания GUI во время длительной операции.
- Сохранять польские и другие Unicode-символы.
- Не скрывать ошибки и не выдавать ложное сообщение об успешной конвертации.
- Не заявлять о поддержке форматов, для которых нет работающего конвертера.

## 4. CSV и JSON: точная семантика

Особое внимание удели требованиям к структурированным данным.

### CSV → JSON

- Кодировка по умолчанию — UTF-8.
- Для чтения CSV с BOM поддерживай `utf-8-sig`.
- Используй `csv.DictReader`.
- Первая строка CSV содержит заголовки.
- Каждый ряд преобразуется в JSON-объект.
- Имена столбцов и порядок ключей должны сохраняться.
- Пустые значения по умолчанию остаются пустыми строками `""`.
- Не преобразовывай автоматически строки в числа, даты, булевы значения или `null` без документированной настройки.
- Поддерживай разделители, предусмотренные настройками или определяемые пользователем.
- Корректно обрабатывай кавычки, запятые внутри значений, пустые поля и переносы строк внутри CSV-полей.
- Обнаруживай дублирующиеся или пустые заголовки и выдавай понятную ошибку, если они делают преобразование неоднозначным.
- Проверяй согласованность количества полей в строках с заголовками.

### JSON → CSV

Задай и опиши в README точную поддерживаемую структуру JSON:

- Верхний уровень — непустой или пустой массив объектов.
- Каждый элемент массива — JSON-объект.
- Все объекты должны иметь совместимую структуру.
- Заголовки CSV формируются из ключей объектов в порядке их первого появления.
- Отсутствующие ключи обрабатываются по явно документированной политике.
- Сложные вложенные объекты и массивы либо сериализуются в JSON-строку в соответствующей ячейке, либо отклоняются с понятной ошибкой. Выбери один вариант и последовательно реализуй его.
- Пустой массив обрабатывается корректно, без падения приложения.
- Невалидный JSON приводит к контролируемой ошибке с описанием проблемы.
- Сохраняй Unicode и польские символы.
- При записи CSV используй `newline=""` и корректную кодировку.

Примеры значений для проверки:

- `Zażółć gęślą jaźń`
- `Łódź`
- `Żółw`
- Пустая строка.
- Значение, содержащее запятую.
- Значение с кавычками.
- Многострочное значение.

### 5.1. Модель запроса

Создай модель `ConversionRequest`, содержащую:

- `source: Path`
- `target_format: str`
- `output_dir: Path`

Добавь отдельную валидацию запроса до начала выполнения конвертации.

### 5.2. Реестр конвертеров

Реализуй централизованный реестр конвертеров.

Пример ожидаемого подхода:

```python
Converter = Callable[[Path, Path], Path]

REGISTRY: dict[tuple[str, str], Converter] = {}
```

Ключ должен однозначно определять пару исходного и целевого форматов.

Предусмотри функции:

- `register_converter()` или декоратор регистрации.
- `available_targets(source)` — возвращает только реально зарегистрированные целевые форматы.
- `is_supported(source_format, target_format)` — проверяет наличие пары.
- `execute(request)` — валидирует запрос и вызывает нужный конвертер.

Не создавай отдельные условные ветки в GUI для каждой конвертации.

**Добавление нового конвертера не должно требовать переписывания интерфейса.** Достаточно реализовать функцию и зарегистрировать её.

### 5.3. Единая обработка ошибок

Создай понятную иерархию исключений, например:

- `ConversionError`
- `ValidationError`
- `UnsupportedConversionError`
- `DependencyMissingError`
- `OutputConflictError`
- `ExternalProcessError`

Можно использовать стандартные исключения там, где это оправдано.

Ошибка должна содержать понятную причину и, когда возможно, следующий шаг для пользователя.

Не используй повсеместно `except Exception: pass`. Не скрывай traceback в логах и не показывай пользователю бессмысленное сообщение «Что-то пошло не так», если причина известна.

## 6. Работа с LibreOffice

LibreOffice требуется для офисных преобразований, для которых выбран этот способ реализации.

### Обязательные требования

1. Определяй доступность LibreOffice на Windows, macOS и Linux.
2. Используй корректный путь к исполняемому файлу.
3. Поддерживай возможность переопределить путь через конфигурацию.
4. Проверяй наличие исполняемого файла до запуска конвертации.
5. Запускай процесс в headless-режиме.
6. Используй аргументы в виде списка, а не командную строку с `shell=True`.
7. Устанавливай разумный тайм-аут.
8. Проверяй код возврата процесса.
9. Сохраняй `stdout` и `stderr` для диагностики.
10. Проверяй, что ожидаемый выходной файл действительно создан.
11. Проверяй, что созданный файл имеет ненулевой размер, когда пустой результат не является допустимым.
12. При ошибке сообщай, как установить LibreOffice или настроить путь к нему.

Пример формы вызова:

```python
result = subprocess.run(
    command,
    capture_output=True,
    text=True,
    timeout=60,
    check=False,
    shell=False,
)
```

Не считай, что любой запуск с кодом возврата `0` гарантирует корректный файл. Проверяй ожидаемый результат отдельно.

Предусмотри конфликты имён и временные каталоги, чтобы не спутать результат с ранее существовавшим файлом.

Учитывай, что LibreOffice может быть уже запущен другим процессом. Если это вызывает конфликты профиля, используй изолированный временный профиль или другую безопасную стратегию.

## 7. Требования к CustomTkinter GUI

Создай полноценное desktop-приложение с современным, аккуратным интерфейсом.

### Визуальная концепция

- Современный интерфейс на CustomTkinter.
- Тёмная тема по умолчанию.
- Аккуратная типографика и единые отступы.
- Чёткая визуальная иерархия.
- Понятные подписи на русском языке.
- Единый стиль кнопок, полей, карточек и сообщений.
- Адаптация к изменению размера окна.
- Без перегруженного интерфейса и ненужных декоративных элементов.

Все элементы интерфейса должны быть функциональными, а не декоративными.

### Основные элементы

**1. Верхняя панель**

- Название `Universal File Converter`.
- Краткое описание приложения.
- Переключатель темы, если реализован корректно.

**2. Выбор исходного файла**

- Поле с путём к файлу.
- Кнопка «Выбрать файл».
- Информация об имени, расширении и размере.
- Проверка файла после выбора.

**3. Формат назначения**

- Поле выбора целевого формата.
- Список форматов формируется динамически на основании реестра.
- При смене исходного файла список обновляется.
- Если доступных форматов нет, пользователь получает понятное сообщение.
- Нельзя выбрать неподдерживаемую пару форматов.

**4. Каталог назначения**

- Поле пути.
- Кнопка «Выбрать папку».
- Проверка существования каталога.
- Возможность выбрать каталог, отличный от каталога исходного файла.

**5. Имя результата**

- Показывай предполагаемое имя выходного файла.
- Имя по умолчанию формируется на основе исходного имени и целевого расширения.
- Не разрешай небезопасные или некорректные имена.
- Обновляй предполагаемый путь при изменении параметров.

**6. Кнопка конвертации**

- Запускает реальную операцию.
- Блокируется, когда параметры невалидны или операция уже выполняется.
- Во время выполнения показывает состояние работы.
- Не позволяет случайно запустить одну и ту же операцию несколько раз.

**7. Статус операции**

Используй понятные состояния:

- Ожидание.
- Проверка параметров.
- Подготовка конвертера.
- Конвертация.
- Успешное завершение.
- Ошибка.

Если процент выполнения неизвестен, не показывай выдуманный прогресс. Используй индикатор неопределённого прогресса.

**8. Результат**

После успешной конвертации показывай:

- Название созданного файла.
- Полный путь.
- Кнопку «Открыть файл».
- Кнопку «Открыть папку».

Используй платформенно-зависимые средства открытия файлов и каталогов с корректной обработкой ошибок.

### Фоновое выполнение

Длительная конвертация не должна выполняться в главном потоке GUI.

Используй рабочий поток или другой подход, совместимый с CustomTkinter.

- Не изменяй виджеты напрямую из рабочего потока.
- Передавай результаты и ошибки в GUI безопасным способом.
- Используй `queue.Queue` и периодический опрос очереди главным потоком либо аналогичную безопасную архитектуру.
- Не вызывай блокирующий `join()` в обработчике кнопки.
- Обеспечь восстановление интерфейса после ошибки.
- Обрабатывай закрытие окна во время выполнения операции.

## 8. Безопасная политика записи файлов

Если целевой файл уже существует, нельзя автоматически его перезаписывать.

Реализуй один из двух вариантов:

1. Диалог подтверждения перезаписи.
2. Автоматическое создание безопасного уникального имени.

Предпочтительно реализовать оба сценария: спросить пользователя, хочет ли он перезаписать файл, и предоставить безопасный альтернативный вариант.

Например:

```text
report.pdf
report (1).pdf
report (2).pdf
```

Проверь конфликт повторно непосредственно перед записью результата. Учти, что файл может появиться после первоначальной проверки.

Для сложных конвертеров используй временный выходной файл или временный каталог. Переноси результат в конечный путь только после успешного выполнения и проверки результата.

Не удаляй и не повреждай исходный файл при ошибке конвертации.

## 9. Валидаторы

Вынеси проверки в отдельный модуль.

Обязательно проверяй:

- Путь к исходному файлу не пуст.
- Исходный файл существует.
- Исходный путь указывает на файл, а не на каталог.
- Расширение исходного файла поддерживается.
- Целевой формат выбран.
- Пара форматов зарегистрирована.
- Каталог назначения существует.
- Каталог назначения доступен для записи.
- Имя выходного файла корректно.
- Конфликт имён обработан.
- Необходимые библиотеки доступны.
- LibreOffice доступен, если нужен.
- Исходный файл не повреждён или его повреждение корректно обнаруживается конвертером.

Не полагайся только на расширение: по возможности проверяй структуру содержимого средствами соответствующей библиотеки.

Для ошибок прав доступа и системных ошибок возвращай понятные сообщения.
