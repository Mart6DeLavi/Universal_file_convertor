# 03 — Usage

This page walks through the GUI workflow: selecting a file, choosing a target format and destination, converting, and handling results and conflicts.

## Window overview

```text
┌───────────────────────────────────────────────────────────────────────┐
│ Universal File Converter          EN | PL      [Light theme switch]   │
│ Local conversion, no uploads · version 1.0.0                          │
├──────────────────────────────────┬────────────────────────────────────┤
│ Source and settings              │ Result                             │
│                                  │                                    │
│ Source file   [path…]  [Browse]  │        No result yet               │
│ Name | Format | Size             │  Choose a source file on the left, │
│ ─────────────────────────────    │  select a target format, and press │
│ Target format [JSON ▾]           │  Convert.                          │
│ CSV table becomes an array …     │                                    │
│ Output folder [path…]  [Browse]  │  Available directions              │
│ Output name   [sample.json]      │  CSV ↔ JSON · TXT ↔ DOCX …         │
│ Result: …/sample.json            │                                    │
│ [          Convert           ]   │                                    │
│ ● Waiting      [████░░░░] 35%    │                                    │
└──────────────────────────────────┴────────────────────────────────────┘
```

The window opens at `1180×720` and can shrink to `1000×620`. There are no scrollable containers; long paths wrap inside their labels.

## Step by step

### 1. Choose a source file

Press **Browse** next to *Source file*, or use the source field. The file dialog filter accepts:

- all supported files: `*.csv *.json *.txt *.docx *.odt`,
- each format separately,
- all files.

When a file is selected:

- the read-only path field shows the absolute path;
- the three tiles show **Name**, **Format**, and **Size** (human-readable);
- the target-format menu is filled with directions available for that format;
- the output folder is set to the source file's folder, unless you already typed or chose another folder in this session;
- the output name is generated as `<source stem>.<target>`;
- the status line changes to *File selected, ready to convert*.

If the format is not supported, a dialog explains why and the status becomes *Unsupported format*. If the format is supported but no direction is available (for example, DOCX with no LibreOffice), the status becomes *No available target formats*.

### 2. Pick a target format

The menu contains only formats that are registered **and** available in the current environment:

| Source | Targets |
|---|---|
| CSV | JSON |
| JSON | CSV |
| TXT | DOCX, PDF |
| DOCX | TXT, PDF\*, ODT\* |
| ODT | PDF\*, DOCX\*, TXT |

\* Requires LibreOffice; the item is absent without it.

Under the menu, a one-line description explains what the conversion does.

Changing the target updates the output name automatically, unless you have edited the name yourself.

### 3. Choose the output folder

- Use **Browse** next to *Output folder*.
- Or type a path and press any key; typing marks the folder as user-selected, so selecting another source will not overwrite it.
- The folder must exist and be writable. A missing folder turns the preview orange and disables **Convert**.

### 4. Adjust the output name

- The name is pre-filled, for example `sample.pdf`.
- Editing it keeps your name when the target changes.
- The extension must match the target; a missing extension is appended.
- Invalid characters, path separators, `.`/`..`, Windows reserved names, and names longer than 200 characters are rejected.
- The preview under the fields always shows the resolved full path.

### 5. Check the preview and convert

The preview line shows `Result: <full path>`. If the file already exists, it appends *file exists, confirmation will be requested*.

Press **Convert**. All inputs are validated once more before the background thread starts. Typical validation failures:

| Situation | Result |
|---|---|
| Source disappeared or is a directory | Dialog with the reason |
| Target or folder missing | Dialog with the reason |
| Folder not writable | Dialog with the reason |
| Source and output are the same file | Dialog with the reason |
| Output name has the wrong extension | Dialog with the reason |
| Output file exists | Overwrite dialog (see below) |

## Overwrite dialog

When the target file exists, a dialog appears with three actions:

| Action | Effect |
|---|---|
| **Cancel** | Nothing is written. |
| **Save as `name (1).ext`** | A free name is generated by incrementing the counter; the request is re-validated and started. |
| **Overwrite** | The existing file is replaced after the new file is successfully produced. |

The source file is never a valid overwrite target: the request is rejected before conversion.

## While converting

- The right panel switches to a centered busy state with a large percentage.
- The progress bar in the left panel fills smoothly. The displayed value never jumps backwards.
- Inputs and the target menu are disabled; the window stays responsive.
- Closing the window during conversion asks for confirmation.

Progress is deterministic in the sense that it is monotonic and ends at 100%; the intermediate values are estimates (the service reports 2%, 8%, 15%, 82%, 90%, 97%, 100% and the GUI smooths them).

## Result state

After a successful conversion the right panel shows:

- **CONVERSION COMPLETE**;
- the output file name and full path;
- **Format**, **Size**, **Time** tiles;
- **Open file** and **Open folder** buttons;
- the note that the source file was not modified.

The status line shows *Done in N.N s · filename* and the progress bar is full.

If a file was opened externally in the meantime or the output folder changed, the open buttons report the problem rather than crashing.

## Error state

If conversion fails, the panel shows:

- **Conversion failed**;
- the message (for example, *LibreOffice was not found*);
- the hint (for example, how to install LibreOffice or set `UFC_SOFFICE`);
- a note that details are in `logs/converter.log`.

The status dot turns red and the status line says *Conversion failed*. Fix the cause and press **Convert** again.

## Theme and language

- The switch in the header toggles **dark** and **light** themes. Dark is the default. The theme is not persisted across launches.
- The **EN | PL** segmented button switches the interface language. The choice is saved as `language` in `~/.config/universal-file-converter/config.json` and restored on the next launch.
- Switching language rebuilds the interface but keeps the selected source, target, output folder, output name, last result, and last error.
- Language cannot be switched while a conversion is running.

## Common scenarios

**CSV → JSON:** select `test_data/sample.csv`, keep the target **JSON**, choose a folder, press **Convert**. The result is an array of objects with headers as keys.

**JSON → CSV:** select `test_data/sample.json`, target **CSV**. The union of keys becomes the header row; nested objects are written as compact JSON text in a cell.

**TXT → PDF:** select `test_data/sample.txt`, target **PDF**. The result is an A4 document with wrapped lines; the font is the first available Unicode font from the built-in list.

**DOCX → PDF:** requires LibreOffice. Select the document, target **PDF**. If the item is missing from the menu, LibreOffice was not detected — see [13 — Troubleshooting](13-troubleshooting.md).

**ODT → TXT:** select the ODT, target **TXT**. Paragraphs and headings become lines; table rows become tab-separated lines.

## Limits of the GUI

- One file per conversion; there is no batch queue.
- The target menu cannot list directions whose dependency is missing.
- The CSV delimiter cannot be chosen in the GUI; use the `UFC_CSV_DELIMITER` environment variable.

For details about what each conversion preserves, see [06 — Conversion pipeline](06-conversion-pipeline.md).
